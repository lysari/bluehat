## Naming Conventions
- Files: PascalCase, named after the main type
- Types: PascalCase; functions and values: camelCase
- Domain terms: `rule`, `rulebook`, `finding`, `check`; never `signature` for a rule (signature means the Ed25519 signature)

## Core Shared Helpers (Do Not Duplicate)
- Loading, checking and accepting signed rules: `RuleFeed` (scans call only `load`; only `FeedReview.check` reaches the network)
- Checking for, verifying and installing app updates: `AppUpdater`, `AppInstaller` (only the buttons in `AppUpdateSection` reach them, through `AppUpdateReview`; the update key in `AppUpdater.trustedKeys` never doubles as a rules key)
- Running system tools and matching text: `Scanner.runTool`, `Scanner.regexes`, `Scanner.matches`
- Finding projects in the user's project folders: `ProjectFolders.directories(in:containing:)`
- Walking the disk in a Deep Scan, with the exclusion list: `VolumeWalk` (never a second walker, no check reads an excluded folder through its own walk, and the walk opens nothing but what `isPackageFile` allows: no hashing, signature checks or tools)
- Parsing or matching an exclude pattern: `ExclusionPattern` (never `NSRegularExpression` on a saved pattern, and picker folders never go through it, since they are exact paths)
- Calling the Security framework on a path a scan found: `SignatureChecks.inspect` (never `SecStaticCodeCreateWithPath` directly, since it can block forever on a FIFO)
- Naming paths in a scan notice: `Scanner.pathList` (tilde, displayable, clipped, at most the `maxNoticePaths` limit unless the caller passes `namingAll: true`)
- Reporting what a scan didn't check: a `NotScannedEntry` returned by the check or added to `NotScannedCollector`, never a notice. A notice is only for what the user has to act on (see Decisions). Show a path with `entry.name`, never `entry.path`, which is raw and only for Show in Finder
- Filtering the findings or Not Scanned list: `FindingsFilter` (never a second matcher). It is for the list only: status, the grid, the menu bar count and history read `ScanStore.visibleFindings`, `issues` and `notes`, and a group action works on the shown group and says so when filtered
- Any limit on what a scan reads, counts, waits for or keeps: a `ScanLimit` in `ScanLimit.all`, read as `limits[.name]` from the `ScanLimits` passed in, never a constant and never read from preferences in core. A new limit gets a range and its reason in `docs/scan-limit.md`, and every production call passes `limits:` (the `.defaults` parameter default is for tests). Limits in `RuleFeed`, `AppUpdater`, `AppInstaller` and signed file validation are trust chain and stay fixed constants
- Moving a scanned copy to the Trash: `ScanStore.moveToTrash` (never a second `trashItem` call; many at once go through `TrashPlan.run` and `ScanStore.moveAllToTrash`, never during a scan)
- Saying which check is running, or a check's status: `CheckProgress`, through `ScanStore.checkProgress` (never a second "first unfinished area")
- Grouping by check area in the findings order: `FindingGroup.ordered` (never a second sort)
- Adding to the ignore list: `SettingsStore.ignore` with a list (`IgnoredFinding.adding`), so the preference is written once
- Creating or reading an offline signing key file: `KeyFile.create` / `KeyFile.read`
- Parsing any JSON file a scan read: `JSONFile.object(from:)` (never `JSONSerialization` directly, since a crafted file crashes it on a 512 KiB stack, the size of the normal stage's), with a refused file listed through `NotScannedEntry.notParsed`
- Reading any file an attacker can influence: `RegularFile.read` / `RegularFile.readStart` / `RegularFile.open`, then `RegularFile.readChunk` for reads in steps (never `FileHandle(forReadingAtPath:)`, `FileManager.contents`, `Data(contentsOf:)` or `FileHandle.read(upToCount:)`, which keeps the bytes until the thread's autorelease pool drains)

## Verification Commands
- Lint: None yet

- Test: `devbox run test`
- Bundle: `devbox run bundle`
- Install: `devbox run install`
- Release: `devbox run release` (builds the DMG and, when the build has an update key, its update signature; uploads nothing)
- Publish: `devbox run publish` (`devbox run publish -- --dry-run` first; refuses without an update signature)

## Decisions
- Stack: Swift + SwiftUI, answered 2026-10-30
- Build: SwiftPM + bundle script, answered 2026-10-30
- Tests: Swift Testing, answered 2026-10-30
- Environment: Devbox, answered 2026-10-30
- Rules: scans use local signed files, updates only through Settings › Rules after the user accepts, decided 2026-11-02
- App updates: user-started from Settings › About, Ed25519 update key separate from the rules keys, fail closed, decided 2026-11-02
- Deep Scan (renamed from full scan): user-started only, scheduled scans stay normal, exclusion list in Settings › General, a cancelled scan restores the last results and records nothing, decided 2026-11-03; it runs the normal scan unchanged, then walks the startup disk at background priority and opens only package files, because the old whole-disk hashing froze the user's Mac, decided 2026-11-04
- Deep Scan control: a custom split pill with two real buttons of equal width, Scan Now in blue and Deep Scan… in indigo, where the right segment opens the confirmation directly and, while a Deep Scan runs, becomes a red Cancel with no icon that fits its text, the left taking the rest; the red is a fixed `Palette.scanPillCancelFill`, not `systemRed`, which is too light for white text; not a split menu (SwiftUI's drops the prominent style and doesn't fill the row) and not a Quick/Deep choice (a remembered mode would turn Scan Now into a whole-disk walk); the indigo is a fixed `Palette.scanPillDeepFill`, not `systemIndigo`, which is too light for white text in dark, decided 2026-11-04
- Findings list: Normal (default) or Grouped by check area, set in Settings › General, decided 2026-11-03; groups collapse with a header button over a `Section` in the `LazyVStack`, never `DisclosureGroup`, whose content isn't lazy, and all expand on each new scan result, so a new threat is never hidden; collapsing isn't saved, decided 2026-11-04
- Group actions: Copy Fix Steps, Ignore All and Move All to Trash in a ⋯ menu beside the header's toggle; no Fix All, on purpose; Move All only acts on copies that already offer Move to Trash, through `ScanStore.moveToTrash`, decided 2026-11-04
- Ignored tab: grouped like the findings list, in a lazy stack and not a grouped `Form`, which creates every row and asks for their whole height; `check` and `severity` on `IgnoredFinding` are optional so saved lists still load, decided 2026-11-04
- Settings window size: one fixed height for every tab, `Metrics.settingsHeight` capped to the screen's visible height, set on the `TabView`; no tab sets its own height, each scrolls by itself and none nests a scroll view in another, decided 2026-11-04
- Panel on top: a switch in Settings › General, on by default; off puts the panel at the normal level and it stays open on losing focus, with the shield raising a panel that has no focus and closing one that does, decided 2026-11-03
- Custom scan: a Custom option in Settings › Schedule runs one normal scan at a saved absolute time, the schedule then turns Off; only a scan started for it counts, so a scan running at that time makes it wait and a cancelled or earlier scan never satisfies it, decided 2026-11-03
- Exclude patterns: `.gitignore`-style globs, not regular expressions, in a second saved list so picked folders stay exact paths; a slash in the middle doesn't anchor a pattern, `!` isn't supported, and a pattern with no literal character is refused as whole-disk, decided 2026-11-04
- Deep Scan coverage: not a finding and not saved in history, says folders read, package files opened and folders that couldn't be read, at the top of the Not Scanned tab; a folder skipped on purpose (excluded, cloud-only, another volume) never counts as unreadable, and "Your Mac looks safe" stays as it was, decided 2026-11-04
- Findings tabs: Findings (N) and Not Scanned (N) in a segmented control, shown once a scan finished and skipped something or was a Deep Scan; one calm line in the status card opens the tab; orange notices stay only for what the user must act on (rules or feed problems, invalid or changed limits, findings left out, a whole-disk exclude, a blocked or cancelled Deep Scan, a Deep Scan stopped at its memory limit, a failed save), decided 2026-11-04
- Not Scanned list: in memory for the latest scan and not in `ScanRecord`; bounded by the `maxNotScannedEntries` limit with true totals, keeping summary rows, then home folder paths, then shallower paths; excludes are the user's choice and aren't listed, but the tab names each, decided 2026-11-04
- Search and filter: an `NSSearchField` for its clear button, Esc and pause in typing; one search across both tabs; reset when a scan starts and ends; group actions act only on the findings shown and state N in their confirmation, decided 2026-11-04
- Scan limits: adjustable in a Settings › Limits tab, the eighth, which fits the toolbar at 500 pt where a ninth would overflow; defaults unchanged, a hard range on each with no 0, a saved value out of range or of the wrong type gets the default and a notice and is never clamped, one `ScanLimits` copied at scan start, a notice names changed values with lowered ones first and doesn't affect status, trust chain limits excluded, decided 2026-11-04
- Crafted JSON: a byte count refuses nesting past `JSONFile.maxNesting` (300) and any NUL byte before parsing, a fixed bound and not a `ScanLimit`; refused files list as Not safe to parse with no finding; the normal stage stays on its concurrency thread, decided 2026-11-04
- Checks grid: areas run one at a time, so one row spins, and none spins while rules load; the Deep Scan's walk is a full-width row under the grid with its own findings count; each row opens a popover of text written from that check's code, and a check that can reach the network through macOS says so in hedged words, decided 2026-11-04
- Other volumes: not Not Scanned entries and not counted, because a Deep Scan stays on the startup disk by design and `/dev` made nearly every Deep Scan report a gap; `Coverage.otherVolumesNote` states it once in the tab's summary, only when a walk ran, and doesn't touch the count, the calm line or `showsNotScanned`, decided 2026-11-04
- Unparsable launch items: a plist the parser rejects or whose top level isn't a dictionary lists as Could not parse with no finding, since launchd's own parser could differ; an empty file, a missing file and a non-regular file stay silent, and a dictionary with no program gives no entry, decided 2026-11-04
- Signature checks: App signing and Launch signing pass `.noNetworkAccess` through `Scanner.signatureValidationFlags`, because results matched with and without it on every tested example and a revoked certificate's status was never mapped to a finding; the text says so and doesn't claim Gatekeeper fills the gap, decided 2026-11-04
- Deep Scan memory limit: a `ScanLimit`, read during the walk only, with the footprint reader injected so tests allocate nothing; at the limit the walk stops, findings and the normal stage stay, and the scan finishes normally. A stopped walk replaces "Your Mac looks safe" with "Deep Scan stopped early" and `.safe` in the menu bar with `.stoppedEarly`, reversing the earlier "stays as it was" for this one case, because unlike a few unreadable folders it leaves most of a disk unread. Its record lists nothing as resolved and is never a comparison baseline, decided 2026-11-04
- Update key backup: one offline file outside any repository, named per command through `UPDATE_KEY_FILE` and never imported into the Keychain, decided 2026-11-03
